自我改进记忆

SELF-IMPROVING MEMORY — META-OPTIMIZATION & HARNESS DISTILLATION

让智能体越干越熟练，关键不在模型参数，而在它怎么用记忆：记什么、怎么整理、什么时候调出来。 过去这些决定靠人手写提示词，而且没有哪一套写法在所有任务上都最好。Meta 这项工作让模型自己来找： 先由一个「元智能体」反复改写记忆提示词，挑出每个任务上表现最好的版本；再让模型带着这些好提示跑一遍， 把提示词换回通用版后拿轨迹去微调——于是提示词教会它的本事，有一部分被写进了权重。

01

问题：记忆要管，但没人知道怎么管最好

一个智能体连续处理一串相关子任务时，前面的经验本该让后面的活干得更好。实现方式是给它一块 持久记忆：每个子任务都在全新会话、空白上下文里开始，唯一能跨任务带走的东西，是一个它用文件工具读写 的记忆目录。记什么、怎么组织、什么时候读回来——这三件事决定了经验能不能真正被复用。

问题在于，这三件事传统上靠人写提示词来规定，而原文先做了一个小型先导实验：准备四种常见的人工记忆策略， 每种都写成一对提示——做完子任务后如何「卸载」经验（OFFLOAD，有时被称作 dreaming，做梦整理）， 以及下一个子任务开始前如何「加载」相关信息（LOAD）——放到三个任务上跑。结论很直接： 没有任何一种策略在三个任务上同时最好，这与 Continual Learning Bench 本身的发现一致。

四种人工记忆策略（优化的种子）

SUMMARY

摘要式

把经历压缩成一段总结带走。简单，但容易长成一整块没索引的大笔记——案例研究里它只拿到 34.3 分。

RETRIEVAL

检索式

强调按需取回：先存细，需要时再按相关性把旧信息捞出来用。

SKILL

技能库式

把经验沉淀成可复用的技能条目，像一本操作手册，后面的子任务直接查手册办事。

HYPOTHESIS

假设追踪式

维护一组待验证的假设及其状态（已确认 / 未测试），随着新证据到来不断更新。

由此得到的主张：既然没有一套记忆设计能通吃所有任务，就不该再让人替模型做这个设计——让模型针对每个任务，自己发现「记什么、怎么组织、何时取回」。

02

舞台：一个故意写得很「素」的通用脚手架

实验的起点是一个通用脚手架（generic harness）：任务智能体 = 任务模型 + 脚手架。脚手架提供文件读写、编辑工具， 和两条与任务无关的指令——子任务开始前的 LOAD 与结束后的 OFFLOAD。 通用版的这两条指令刻意写得极简，只让模型「用文件工具管好你的记忆」，具体策略完全留给模型自己。 每个子任务结束后，实时上下文被清空，只有记忆目录里的文件能活到下一轮。

关键细节：模型可以在子任务一开始就读记忆（比如先看 README.md），也可以等解题过程中再按需读取—— 读的时机本身也是策略的一部分。通用脚手架的问题不是不能用，而是太笼统： 换上更具体、更贴合任务的 LOAD / OFFLOAD 指令，成绩能明显变好。问题只剩一个：好的指令去哪儿找？

03

方法：发现 — 示范 — 蒸馏

Self-Improving Memory 是一条三步流水线（Discover–Demonstrate–Distill），分两个阶段完成。 最特别的一点：元智能体和任务智能体是同一个模型（Kimi-K2.6）——模型最终是在学它自己发现的记忆技能。

让元智能体反复改写记忆提示词

元优化循环里有两个角色：元智能体负责读轨迹、找毛病、提修订；外层循环负责真跑评估、用分数决定谁留下。 轨迹很长，元智能体分三层处理：先逐个子任务做摘要，再逐次完整运行做分析，最后跨运行汇总证据，写出新版 LOAD / OFFLOAD。

初始化候选池：4 套人工种子脚手架→ 每个候选完整跑任务流 5 次→ 按平均分选前 4 名当「父母」→ 元智能体读轨迹与记忆目录，诊断反复出现的失败→ 提出修订版，入池再评估↺
  • 选择依据是留出集上的平均分，与元智能体能看到的训练子任务分开，避免对着答案改提示。
  • 优化的对象只有 LOAD / OFFLOAD 两条指令——即「如何管理记忆目录」，不碰其他脚手架部件。
  • 搜索并不温顺：全部已完成搜索中，44 个修订版有 37 个没能超过此前最佳。评估与保留最优，是涨分的前提，不是装饰。

把好提示的行为，搬进权重里

示范（Demonstrate）：选每个任务上得分最高的优化脚手架，让基础模型带着它在训练子任务上运行，完整记录每一次模型调用——提示、回复、推理、工具调用与工具返回。

换提示（关键一步）：把记录中出现的优化版 LOAD / OFFLOAD，逐处替换回通用版，模型的回复原样保留。这一步成立的原因是：优化脚手架规定的是记忆的设计方式，通用脚手架只是把同样的选择权交还给模型——在优化提示下做出的行为（如何组织文件、记哪些事实、复用哪种解题套路），在通用提示下同样「说得通」。

蒸馏（Distill）：把三个任务的示范轨迹汇成一个数据集做微调，损失只计算在助手的输出 token（推理与工具调用）上，指令、任务请求和工具返回都被掩码。实现上用 LoRA（rank 64，作用于注意力投影层）。

优化提示下运行 → 记录轨迹→ 提示换回通用版，回复不变→ 在「通用提示 + 好行为」上微调→ 部署时只用通用脚手架

被示范的行为长什么样？例如把记忆拆成 QUICKSTART.md（仓库元信息）、REGISTRY.md（可复用修复索引）、 SCHEMA.md（模式事实）；记下表关系、价格单位、测试命令；养成「改代码前先跑测试、聚合前先核对 join 键」的套路。

04

结果：提示能涨 19.9 分，权重能留住其中一部分

实验设置：Kimi-K2.6 同时担任任务智能体与元智能体；每个任务流的前段作训练子任务、后段作测试子任务， 分界点正落在基准刻意设计的环境切换（phase transition）处，所以测试分衡量的是同一任务内、分布变化之后的泛化。 切换下面的按钮，对比两个阶段的成绩（均为三项任务平均分）。

三条值得记住的读数

  • 优化是真涨，不是挑出来的幻觉吗？原文同时说明：人工种子与优化脚手架都按任务分挑选「已评估候选中的最佳」，口径一致；三项任务上优化版全部胜出，平均 56.0 vs 44.6。
  • 涨分来自经验积累，而非起跑线。Spectrum 上两者第一个子任务几乎同分（21.7 vs 21.9），但跑到测试段拉开到 42.5 vs 49.9——记忆越攒越值钱，正是持续学习想要的效果。
  • 蒸馏只留住一部分。56.0 是「带着优化提示跑」的成绩；蒸馏后回到通用提示是 43.1。提示的增益没有全部进权重，但比「拿模型自己的通用轨迹微调」实打实多 5.5 分——说明轨迹的质量（由谁示范）比单纯多训一轮重要。

案例：Codebase 的记忆脚手架是怎样被改出来的

原文用 Codebase 任务追踪了元智能体的修订链。每一步的改动都来自对上一版轨迹的「诊断报告」—— 点下面的卡片，看分数和改法如何一步步演化。注意最后那个反例：同一轮里另一条修订路线，因为删得太狠，反而掉回 36.6。

测试分 34.3 · 参照：通用脚手架 33.5 / 最佳种子 43.7

摘要式：笔记越写越臃肿

摘要式种子只比通用版（33.5）高一点点。轨迹诊断指出两个病灶：笔记长成一整块没有结构的「巨石」， 以及每个子任务都在重复摸索仓库结构——记了，但记的东西不好用。

06

怎么读这项工作

它在已有研究版图里的位置、成立的条件，以及还没解决的问题——都按原文的说法来。

定位

搜的只是「记忆说明书」

已有的脚手架优化有的搜整个智能体设计，有的让智能体改自己的代码。本文只搜管记忆的两条指令。正因为优化版与通用版只差这两条指令，蒸馏才能靠「把提示换回去」一步完成，不需要额外的纠错智能体。

自举

老师和学生是同一个模型

元智能体与任务智能体同为 Kimi-K2.6。被写进权重的，是模型自己发现的技能——这也是标题里「自我改进」的确切含义，而不是外部强模型喂数据。

条件

搜索离不开评估与选择

44 个修订版里 37 个不如既往最佳；Database 与 Spectrum 第一代就到顶，Codebase 磨到第四代。没有可靠的留出集打分和「只留最优」的纪律，元智能体的提案本身并不涨分。

边界

增益只内化了一部分，且只在同任务内验证

蒸馏后 43.1 仍明显低于带着优化提示跑的 56.0；测试是同一任务流后段的分布变化，不是跨任务迁移。原文也坦承：增益有多少来自记忆组织本身、多少来自解题行为，还需要直接的行为分析来分离。

作者们的下一步：把这套「发现—示范—蒸馏」从记忆扩展到更多的智能体能力，并在更广的任务与模型上验证。对做 agent 的人来说，眼下最可迁移的经验是那条修订链：记忆的价值不在记得多，而在结构——一个快速上手文件、一个带索引的登记表、一类事实一个文件。
